Loot entry

A lootentry_ (or an inline map on a pool) is one weighted outcome. Weight <= 0 is skipped. Default weight is 1. Failed entry requirements skip that row.

KeyStatusNotes
typeLiveITEM CURRENCY TABLE_REFERENCE POOL_REFERENCE ITEM_CATEGORY COMMAND TEXT
referenceidLiveItem, currency, table, or pool script, category name, chat text, or command string (no slash)
baseweightLiveDefault 1. Weight <= 0 is skipped
quantityLiveInteger, or { min: n, max: n }
weight_modifiers / weightmodifiersLiveKeyed rows. See Weight
requirements / conditionsLiveSkip this entry when they fail
upgradesLiveSequential. See Upgrade
configLiveUnwrap one nested map (old Frontend shell)

COMMAND is a Minecraft command string run as the player. It is not a Denizen task name.

Weight​

Rows run in key order. stat is the effective level on the recipient. A missing level is 0. If amount is set, it is used instead of the stat. After a row, weight cannot exceed cap.

KeyNotes
modeADD_FLAT MULTIPLY_BASE SET_MIN
statEffective level on the recipient. Missing level is 0
amountIf present, used instead of the stat
capAfter this row, weight cannot exceed this

Upgrade​

Keyed sequential rows. Each may unwrap config:. Later rows see the new type and id.

KeyNotes
requirementsMust pass
chanceSame as Eventstat (0 to 1, or 0 to 100)
new_typeReplaces type when the row hits
new_referenceidReplaces referenceid when the row hits

Item categories​

Item Config categories: is a list (hat). Reload builds server.flag[item_categories] once (rebuild_item_category_index). list_items_in_category and pick_item_script_in_category read that map. They do not scan every item_* on a roll.

ITEM_CATEGORY with referenceid: hat becomes a normal ITEM grant of a random script from that list. An empty category yields nothing. The index is built in reload_all_server_flags, so a category added in the same session is empty until reload.

Grant​

TypeAction
ITEMCost Component GIVE (same as shops). Counts as item obtained
CURRENCYAPPLY_TRANSACTION GIVE path. Wallet or ITEM form stacks, from Frontend form
TEXTnarrate to the player
COMMANDexecute as_player with referenceid as the command
TABLE_REFERENCE / POOL_REFERENCEFlattened into child rolls. Depth cap is on Loot
ITEM_CATEGORYFlattened into ITEM

Non-players are skipped. Missing item or currency scripts are skipped. The nested roll itself is on Loot.
